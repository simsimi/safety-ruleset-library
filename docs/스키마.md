# riskcheck 스키마

위험판별 테스트 소프트웨어의 데이터 계약이다. 테스트셋·결과는 JSONL, 사전은 YAML,
스키마 정의는 JSON Schema(draft 2020-12), 리포트는 JSON + Markdown + HTML을 쓴다.

## 파일 구성

| 파일 | 내용 |
|---|---|
| `schemas/testset.schema.json` | 테스트셋(JSONL 한 줄)의 스키마 |
| `schemas/dictionary.schema.json` | 단어 사전(YAML)의 스키마 |
| `schemas/predictions.schema.json` | 단계별 판정 결과(JSONL 한 줄)의 스키마 |
| `schemas/report.schema.json` | 평가 리포트(JSON)의 스키마 |
| `examples/` | 스키마를 따르는 예시 4종 (테스트셋 12건, 사전 발췌, 판정 결과, 계산된 리포트) |
| `tools/validate_examples.py` | 예시 검증 + 리포트 예시 생성 스크립트 |

## 판정 체계

판정은 **위험/비위험 이진**이다 (`risk` / `none`). 사전 패턴이 걸리거나 모델 신호가
임계값을 넘으면 `risk`, 아니면 `none`이다. 패턴에는 등급을 두지 않는다.

테스트셋의 정답 `label`은 기록용으로 `none` / `danger` / `emergency` 3값을 유지하지만,
채점할 때는 `danger`와 `emergency`를 `risk`로 접어 이진으로 계산한다.

- `danger` — 자기를 해치는 생각 (예: 죽고 싶다, 사라지고 싶다)
- `emergency` — 이미 벌어졌거나 곧 벌어지려는 상황 (예: 약을 다 먹었다, 유서를 썼다)

## 1. 테스트셋 (`testset.schema.json`)

JSONL, 한 줄에 발화 하나.

| 필드 | 필수 | 설명 |
|---|---|---|
| `id` | O | 유일 식별자. predictions·리포트가 이 id로 연결된다 |
| `text` | O | 발화 원문. 정규화하지 않은 그대로 |
| `label` | O | 정답 라벨 (`none`/`danger`/`emergency`). 채점 시 이진으로 접힌다 |
| `sublabels` | - | 하위 라벨 `{depression, anxiety}`. 각 값은 `true`/`false`/`null`(판정 보류). 최종 판정에 쓰지 않고 모델 단계의 성능 보정에 쓴다 |
| `certainty` | - | 축별 확실성 `{grade, depression, anxiety}`, 값은 `certain`/`ambiguous`/`needs_context`. `needs_context` 항목은 채점에서 제외한다 |
| `certainty_reason` | - | 축별 확실성의 근거 문장 |
| `source` | - | 출처. 예: `rule-test`(규칙 테스트 케이스 변환), `human`(사람 기준 라벨) |
| `note` | - | 라벨 근거, 소그룹 태그 등 자유 메모 |

## 2. 단어 사전 (`dictionary.schema.json`)

YAML. 사람이 읽고 고치는 파일이라 주석이 가능한 YAML로 했다.

최상위: `name`, `version`(필수), `patterns`(필수), `excludes`, `description`.

패턴 항목:

| 필드 | 필수 | 설명 |
|---|---|---|
| `id` | O | 소문자·숫자·`-`·`_`만. predictions가 이 id를 참조한다 |
| `type` | O | `phrase`(공백 제거 후 부분 문자열 매칭, 패턴도 공백 없이 표기) / `regex`(공백을 한 칸으로 줄인 원문에 정규식 검색) |
| `pattern` | O | 구 또는 정규식 원문 |
| `category` | - | 자유 태그. 예: `suicide`, `self_harm` |
| `enabled` | - | 기본 `true`. `false`면 패턴을 지우지 않고 끈다 |
| `note` | - | 근거 메모 |

구 사전 형식의 `level` 필드는 로더가 무시하므로, 등급이 적힌 기존 사전도 그대로 쓸 수 있다.

제외 패턴(`excludes`) 항목: `id`, `pattern`(필수), `type`은 `regex`만, `enabled`, `note`.

- 제외는 매칭보다 먼저 적용해, 위험이 아닌 구간을 지운다.
- 사전의 `excludes`는 정규식 구간 제거만 담당한다. 절(clause) 단위 판정이 필요한 제외 —
  "죽고 싶냐"·"자살해라"처럼 틀림없이 듣는 상대에게 하는 말만 골라 빼는 규칙 — 은
  탐지기 내장 규칙으로 둔다. 애매한 경우는 빼지 않는다.

## 3. 단계별 판정 결과 (`predictions.schema.json`)

JSONL, 한 줄이 발화 하나에 대한 **한 단계**의 결과다. 단계를 파일 단위로 분리 저장하므로
사전만 바뀌면 사전 단계만 다시 만들고, 임계값·정책 변경은 재실행 없이 재채점만 한다.

| 필드 | 필수 | 설명 |
|---|---|---|
| `id` | O | 테스트셋 항목 id |
| `stage` | O | `dict`(사전 단계) / `model`(모델 단계) |
| `predicted` | O | 판정 (`risk`/`none`). 판정 실패 시 `null` |
| `matches` | O | 걸린 패턴 목록. `none`이거나 오류면 빈 배열 |
| `matches[].pattern_id` | O | 사전 패턴 id |
| `matches[].matched` | - | 실제로 걸린 문자열 |
| `matches[].span` | - | `[시작, 끝)` 위치. regex처럼 원문 위치가 있는 경우만. phrase는 공백 제거 텍스트 기준이라 생략 |
| `scores` | - | 모델 단계 전용 `{depression, anxiety, else}` (각 0~1, 합 1) |
| `source_version` | - | 이 결과를 만든 사전/모델 버전. 재실행 여부를 가르는 키 |
| `error` | - | 판정 실패 사유. 오류 건은 지표 분모에서 제외한다 |

## 4. 평가 리포트 (`report.schema.json`)

- `schema_version`, `stage` (`dict`/`model`/`combined`)
- `counts` — `{total, evaluated, errors}`. `total = evaluated + errors`여야 한다
- `overall` — `{accuracy, macro_f1}` (이진 기준)
- `per_label` — 라벨별 `{precision, recall, f1, support}`. 분모가 0인 지표는 `null`
- `confusion` — 혼동행렬. 행=정답, 열=예측
- `sublabel_metrics` — 모델 단계의 우울/불안 하위 라벨 지표 (모델 단계 리포트의 본체)
- `pattern_stats` — 사전 단계의 패턴별 매칭·오탐 건수
- `contribution` — 통합 단계의 단계별 포착·오탐 기여 분해
- `false_positives`, `false_negatives` — `{id, gold, predicted}` 전체 목록
- `error_cases` — `{id, error}` 목록
- `dataset`, `dictionary` — 평가에 쓴 테스트셋 이름·건수와 사전 이름·버전
- `generated_at` — 생성 시각 (선택)

`report_dict` / `report_model` / `report_combined` 리포트(MD·HTML)는 이 JSON과 같은
수치를 렌더링한 것이며 별도 스키마를 두지 않는다. 단계별 구성은 `docs/모델_단계.md`와
README의 리포트 안내를 참고한다.

## 스키마로 표현 못 하는 규칙 (검증 도구 책임)

- 테스트셋 `id`, 사전 패턴 `id`의 파일 내 유일성
- predictions의 id 집합과 테스트셋 id 집합의 일치
- `matches[].pattern_id`가 사전에 실제 존재하는지
- `counts.total = counts.evaluated + counts.errors`

위 4개는 `tools/validate_examples.py`가 예시에 대해 실제로 검사한다.
예시를 검증하면 스키마 4종과 예시 12건이 통과하고, 예시 리포트는
accuracy 0.8333, macro F1 0.8286, 위험 Recall 0.8571로 계산된다 (12건 소규모 예시 기준).
